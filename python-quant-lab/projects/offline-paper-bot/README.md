# โปรเจกต์จบ — บอท paper แบบออฟไลน์

## เป้าหมาย

สร้างโปรแกรมที่อ่าน OHLCV จากไฟล์ท้องถิ่น สร้างสัญญาณที่ทำซ้ำได้ จำลองคำสั่งซื้อขาย คิดค่าธรรมเนียม ติดตามเงินสดและสินทรัพย์ บังคับขีดจำกัดความเสี่ยง และบันทึกเหตุการณ์

โปรเจกต์นี้ใช้ standard library และชุดข้อมูลสังเคราะห์ใน <code>data/synthetic_btc_ohlcv.csv</code> เท่านั้น ไม่มี network client, exchange API, wallet, private key หรือ live order ห้ามเพิ่มการเชื่อมต่อหรือส่งคำสั่งเงินจริง

## ผู้ใช้และปัญหา

ผู้เรียน Python ใช้โปรเจกต์นี้เพื่อดูว่าฟังก์ชันคำนวณ สัญญาณ ข้อมูลราคา และ accounting ทำงานร่วมกันอย่างไร การจำลองช่วยหาบั๊กและตรวจ invariant ก่อนศึกษา paper-forward test ในระบบแยก

## ข้อกำหนด

1. อ่านไฟล์ CSV ออฟไลน์และตรวจว่ามี header/คอลัมน์ครบ
2. ตรวจ timestamp เรียงจากเก่าไปใหม่และไม่ซ้ำ
3. ตรวจราคาเป็นบวก, volume ไม่ติดลบ, high >= max(open, close), low <= min(open, close) และ low <= high
4. สร้างสัญญาณจากข้อมูลที่รู้แล้วเท่านั้น; ถ้าสัญญาณคำนวณหลังปิดแท่ง ให้จำลอง execution ในแท่งถัดไป
5. เริ่มด้วย bankroll จำลอง 100 หน่วยเงิน ใช้ fee ทั้งตอนเข้าและออก
6. จำกัดมูลค่าคำสั่งไม่เกิน 25 และจำนวนสินทรัพย์ไม่เกิน 0.2 หน่วย
7. ห้ามซื้อเมื่อเงินสดไม่พอ และหยุด/ปฏิเสธเมื่อข้อมูลหรือความเสี่ยงไม่ผ่าน
8. บันทึกเวลา action ราคา จำนวน fee เงินสด และจำนวนสินทรัพย์
9. คำนวณ net P&L และ drawdown จาก equity curve
10. การรันด้วยไฟล์และพารามิเตอร์เดิมต้องได้ผลเหมือนเดิม

## ขั้นตอนสร้าง

1. อ่าน <code>starter.py</code> และวาด flow: load → validate → signal → paper execution → account → report
2. ทำ validator ให้ผ่าน malformed rows ก่อน
3. เขียน strategy เป็นฟังก์ชันบริสุทธิ์ที่ไม่อ่านไฟล์และไม่เขียน global state
4. แยก paper broker ออกจาก strategy
5. หลังทุก event ตรวจ invariant: cash >= 0, quantity >= 0 และ equity = cash + quantity × mark price
6. ทดสอบกรณีปกติ ราคาเป็นศูนย์ เวลาไม่เรียง fee สูง เงินสดไม่พอ และข้อมูลไม่ครบ
7. รันซ้ำและเปรียบเทียบ report/log

## เกณฑ์ตรวจรับ

- ใช้ข้อมูล local และไม่เปิด network
- ข้อมูลผิดรูปแบบถูกปฏิเสธพร้อมข้อความที่ช่วยชี้แถว
- สัญญาณไม่ใช้ข้อมูลอนาคต
- ค่า fee ลด net P&L เมื่อเทียบกับการคำนวณเดียวกันที่ fee เป็นศูนย์
- คำสั่งทุกครั้งผ่าน risk limit
- accounting invariant เป็นจริงหลังทุก event
- มี log ที่อ่านย้อนกลับได้และผลลัพธ์ทำซ้ำได้
- มี tests สำหรับ expected behavior และ negative cases
- รายงาน benchmark/ข้อจำกัดและไม่กล่าวอ้างว่าผล backtest พิสูจน์ edge

python projects/offline-paper-bot/reference.py
