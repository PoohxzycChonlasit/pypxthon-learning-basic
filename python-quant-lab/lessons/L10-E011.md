# L10-E011 — ปรับปรุงจำนวนสถานะ

**ระดับ:** Level 10 — วิศวกรรม paper bot ออฟไลน์<br>
**ความยาก:** Tier 3 — ปานกลาง — หลายขั้นตอน<br>
**ชนิดคำตอบ:** เขียนฟังก์ชันและคืนค่าด้วย return

## 1. เรียนรู้อะไร

buy คืน +quantity; sell คืน -quantity; side อื่นหรือ quantity ไม่ถูกต้องคืน 0

## 2. ก่อนเริ่ม

ทบทวน: [L10-E010](L10-E010.md). หากคำศัพท์ในโจทย์ยังไม่คุ้น ให้เริ่มจากคำอธิบายแนวคิดในหน้านี้ก่อน

**แนวคิดสำคัญ:** แนวคิด: buy คืน +quantity; sell คืน -quantity; side อื่นหรือ quantity ไม่ถูกต้องคืน 0

ขั้นตอน: ตรวจ quantity; ตรวจ side; ใส่เครื่องหมายตาม buy/sell

## 3. ตัวอย่างสั้น

ตัวอย่างนี้ฝึกแนวคิดที่เกี่ยวข้อง แต่ใช้ค่าและสถานการณ์แยกจากโจทย์ที่ต้องส่ง

~~~python
import json
settings = json.loads('{"mode": "offline", "retry": 2}')
print(settings["mode"], settings["retry"])
~~~

อ่าน arguments ที่ส่งให้ฟังก์ชันแล้วตามค่าที่ return; ถ้าไม่มี print การคืนค่าไม่ได้แสดงใน Terminal

## 4. งานของคุณ

สถานการณ์: ระบบบัญชีแปลง side และ quantity เป็นการเปลี่ยนแปลง position แบบมีเครื่องหมาย

เขียน position_update(event) ตามสัญญา: buy คืน +quantity; sell คืน -quantity; side อื่นหรือ quantity ไม่ถูกต้องคืน 0.

กรณีขอบ: quantity ต้อง finite และไม่ติดลบ; ไม่มีการเปิดสถานะจริง.
ใช้ข้อมูลจำลองออฟไลน์เท่านั้นและคืนค่าตามโจทย์

## 5. เขียนคำตอบที่ไหน

## 6. ลำดับทำงาน

1. อ่าน signature position_update(event) และดูว่า parameter แต่ละตัวรับข้อมูลอะไร
2. แก้เฉพาะ body ที่โจทย์กำหนด และส่งผลด้วย return
3. ตรวจกรณีขอบที่ระบุ โดยคงชื่อฟังก์ชันและ signature
4. ใช้ run ดูค่าคืนจากกรณีแรก แล้วใช้ check ตรวจ test ทั้งหมด

## 7. ข้อมูลเข้าและผลลัพธ์

- **ข้อมูลเข้า:** grader เรียก position_update ด้วย parameters ตาม signature ที่ให้.
- **ผลลัพธ์:** ฟังก์ชันต้องคืนค่า (int); return ส่งค่ากลับ ส่วน print แสดงข้อความ.
- **ชุดตรวจ:** มี 2 กรณี รวมขอบเขตตามโจทย์

ข้อจำกัดที่ต้องรักษา: Python 3.12; quantity ต้อง finite และไม่ติดลบ; ไม่มีการเปิดสถานะจริง; ไม่มีการเชื่อมต่อ exchange หรือ wallet

## 9. ถ้าไม่ผ่าน
