# L10-E003 — เติม validator ของ paper order

**ระดับ:** Level 10 — วิศวกรรม paper bot ออฟไลน์<br>
**ความยาก:** Tier 3 — ปานกลาง — หลายขั้นตอน<br>
**ชนิดคำตอบ:** โปรแกรม Python แสดงผล (stdout)

## 1. เรียนรู้อะไร

ตรวจ side, ราคา, จำนวน, เงินสด และ notional limit ก่อนรับคำสั่ง

## 2. ก่อนเริ่ม

ทบทวน: [L10-E002](L10-E002.md). หากคำศัพท์ในโจทย์ยังไม่คุ้น ให้เริ่มจากคำอธิบายแนวคิดในหน้านี้ก่อน

**แนวคิดสำคัญ:** ตรวจเงื่อนไข risk ก่อนเปลี่ยน state ของพอร์ต

## 3. ตัวอย่างสั้น

ตัวอย่างนี้ฝึกแนวคิดที่เกี่ยวข้อง แต่ใช้ค่าและสถานการณ์แยกจากโจทย์ที่ต้องส่ง

~~~python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.price = price
tea = Product("tea", 20)
print(tea.name, tea.price)
~~~

ในตัวอย่างนี้ ให้ดูว่าคำสั่ง print ส่งค่าใดไปยังหน้าจอ; ข้อความหลังเครื่องหมาย # เป็นคำอธิบาย output ของตัวอย่าง

## 4. งานของคุณ

เติม order_allowed(cash, quantity, price, max_order_value) ให้คืน bool เท่านั้น อนุญาตเมื่อ cash ไม่ติดลบ, quantity/price เป็นบวก, notional ไม่เกิน max_order_value และไม่เกิน cash โปรแกรมรับค่าทีละบรรทัด; input ไม่มี side field

ไฟล์ส่งคำตอบ: [exercises/level_10/L10-E003.py](../exercises/level_10/L10-E003.py)

## 6. ลำดับทำงาน

1. อ่านโจทย์และตัวอย่างแยก แล้วหา TODO หรือบรรทัดที่ต้องแก้ในไฟล์ Python
2. เขียนคำสั่งให้แสดงผลตรงตามรูปแบบที่โจทย์ขอ
3. บันทึกไฟล์ แล้วใช้ run ดูกรณีตัวอย่างแรก
4. ใช้ check ตรวจทุกกรณี; อ่านชื่อ test แรกที่ไม่ผ่านก่อนแก้

## 7. ข้อมูลเข้าและผลลัพธ์

- **ข้อมูลเข้า:** ใช้ input ที่โจทย์หรือ test ส่งให้; ถ้าไม่มี stdin ก็ไม่ต้องพิมพ์ค่าเพิ่ม.
- **ผลลัพธ์:** ข้อความที่โปรแกรมส่งไป stdout ต้องมีลำดับ บรรทัด และรูปแบบตรงตามโจทย์.
- **การแสดงผล:** print() แสดงค่าที่ Terminal; การกำหนดตัวแปรอย่างเดียวไม่ทำให้เกิด output

ข้อจำกัดที่ต้องรักษา: ใช้ Python 3.12 และ standard library; ห้ามแก้ tests, curriculum หรือไฟล์เฉลย; ตัวอย่างการเทรดเป็น paper-only

## 9. ถ้าไม่ผ่าน

สิ่งที่พลาดง่าย: เช็กแค่เงินสดแล้วไม่ตรวจ notional limit หรือราคาศูนย์. ตรวจเครื่องหมายคำพูด การขึ้นบรรทัดใหม่ และค่าที่ print ทีละบรรทัด
