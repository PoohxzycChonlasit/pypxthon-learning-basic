# คู่มือเรียน Quant อย่างระมัดระวัง

Quant research คือการตั้งคำถามทางการเงินให้ชัด แปลงเป็นกฎที่ตรวจได้ เตรียมข้อมูล ตรวจการคำนวณ และพิจารณาความไม่แน่นอน หลักสูตรนี้ใช้ข้อมูลสังเคราะห์และการจำลองออฟไลน์ ไม่ดึงราคาตลาดจริงและไม่เชื่อมต่อบัญชีซื้อขาย

## เส้นทางจาก Python ไปสู่ Quant

เรียน Python พื้นฐานและการจัดการไฟล์ใน Levels 1–5 ก่อน ต่อด้วยสถิติใน Level 7 และการเงิน/ความเสี่ยงใน Level 8; Levels 9–10 ใช้ข้อมูลตามเวลาเพื่อทำวิจัยและจำลอง paper แบบออฟไลน์ หากต้องการฝึกการอ่านและวิเคราะห์ตารางเชิงลึก ให้ทำ [Data Analysis Practice Track](../tracks/data_analysis/README.md) หลัง Level 5: DA01–DA05 ใช้ standard library และ DA06 เป็นต้นไปใช้ NumPy/pandas ตาม dependency ที่ระบุ

ชุด OHLCV และ trade log ใน [คู่มือข้อมูลฝึก](../data/README.md) สร้างจาก seed คงที่เพื่อฝึกเท่านั้น ไม่ใช่ราคาจริงหรือหลักฐานว่ามีกลยุทธ์ที่ทำกำไร

## ลำดับการวิจัย

1. **เขียนสมมติฐานก่อนดูผล** — ระบุเหตุผล กลไกที่คาดว่าจะเกิด และเงื่อนไขที่ทำให้สมมติฐานผิด
2. **ตรวจข้อมูล** — เวลาเรียงถูก ไม่มีข้อมูลอนาคตปะปน ค่าราคาเป็นบวก และ OHLC ผ่านข้อกำหนด `high >= max(open, close)` กับ `low <= min(open, close)`
3. **กำหนด benchmark** — เปรียบเทียบกลยุทธ์กับการไม่ทำอะไรหรือเกณฑ์ง่าย ๆ เพื่อแยกผลที่มาจากตลาดออกจากกฎของเรา
4. **คิดต้นทุน** — รวม fee, spread, slippage และ funding เมื่อเกี่ยวข้อง ผลตอบแทนขั้นต้นไม่ใช่กำไรสุทธิ
5. **แยกเวลา** — ใช้ข้อมูลช่วงแรกพัฒนากฎ และช่วงหลังที่ไม่เคยใช้เลือกกฎเป็น out-of-sample ตรวจซ้ำแบบ walk-forward เมื่อทำได้
6. **จำลองอย่างระมัดระวัง** — เริ่มจากการคำนวณในไฟล์และ paper trading ออฟไลน์ ตรวจบัญชีเงินสด ปริมาณสินทรัพย์ และขีดจำกัดความเสี่ยงทุกครั้ง
7. **รายงานข้อจำกัด** — บอกจำนวนตัวอย่าง ค่าใช้จ่ายที่ไม่รวม สมมติฐาน และเหตุผลที่ผลอาจไม่เกิดซ้ำ

## สูตรพื้นฐาน

ผลตอบแทนอย่างง่ายระหว่างราคาเริ่มต้น `P0` และราคาปลายทาง `P1` คือ `(P1 / P0) - 1` ต้องมี `P0 > 0` Log return คือ `ln(P1 / P0)` และนิยามไม่ได้เมื่อราคาไม่เป็นบวก

กำไรขั้นต้นสถานะ long จำนวน `q` คือ `(ราคาออก - ราคาเข้า) × q` กำไรสุทธิหักค่าใช้จ่ายทุกด้าน เช่น fee ตอนเข้าและออก Slippage เป็นส่วนต่างจากราคาที่คาดว่าจะได้ ไม่ควรถือว่าเป็นศูนย์โดยไม่มีเหตุผล

ขนาดสถานะไม่ควรเลือกจากผลกำไรที่อยากได้ ให้เริ่มจากวงเงินขาดทุนสูงสุดที่ยอมรับได้ หารด้วยความเสี่ยงต่อหน่วย แล้วตรวจ exposure รวมและขีดจำกัดพอร์ต ระวังการทบต้นและ drawdown เพราะการขาดทุนต้องการกำไรเปอร์เซ็นต์ที่มากขึ้นเพื่อกลับสู่จุดเดิม

Sharpe ratio, profit factor และ win rate สรุปข้อมูลบางมุม แต่ไม่ได้บอกว่ากลยุทธ์จะทำกำไรในอนาคต ตัวอย่างน้อย ต้นทุนผิด และการเลือกพารามิเตอร์หลังเห็นผลทำให้ตัวเลขดูดีกว่าความจริงได้

## อคติที่ต้องรู้

- **Look-ahead bias:** สัญญาณ ณ เวลาหนึ่งแอบใช้ข้อมูลที่ยังไม่เกิด ณ เวลานั้น
- **Data leakage:** ข้อมูลจากช่วงประเมินไหลกลับไปใช้ตอนสร้างโมเดลหรือเลือกกฎ
- **Overfitting:** ปรับกฎให้เข้ากับ noise ในข้อมูลอดีตจนใช้กับข้อมูลใหม่ไม่ได้
- **Survivorship bias:** เหลือเฉพาะสินทรัพย์ที่ยังอยู่ ทำให้ประวัติที่เห็นดูแข็งแรงเกินไป
- **Multiple testing:** ทดลองกฎจำนวนมากแล้วเลือกเฉพาะตัวที่บังเอิญชนะ

ทดสอบโดยเลื่อนจุดเริ่มต้นของข้อมูล ตรวจว่าแต่ละสัญญาณใช้ได้เฉพาะข้อมูลอดีต และเก็บ benchmark ที่กำหนดไว้ก่อน ห้ามเลือกผลลัพธ์จากชุด test ซ้ำ ๆ แล้วเรียกชุดนั้นว่า out-of-sample

## ขอบเขตการเรียน

ข้อมูล OHLCV ใน `data/` เป็นข้อมูลสังเคราะห์สำหรับฝึก ไม่ใช่ประวัติ BTC/ETH จริง ฟังก์ชันประเมินผลในแบบฝึกหัดไม่ใช่คำแนะนำลงทุน แบบจำลองและผล backtest ไม่พิสูจน์ edge หรือรับประกันกำไร บอท final project ต้องทำงานออฟไลน์และห้ามเพิ่มการส่งคำสั่งเงินจริง
