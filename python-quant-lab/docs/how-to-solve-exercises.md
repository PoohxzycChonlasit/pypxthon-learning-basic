# วิธีทำแบบฝึกหัดให้เข้าใจ

การแก้โจทย์ที่ดีเริ่มจากเข้าใจความต้องการก่อนพิมพ์โค้ด ใช้วงจรนี้ทุกข้อ:

**อ่านบทเรียน → พิมพ์ตัวอย่างเอง → ทดลองเปลี่ยนค่า → แยก input/process/output → เขียนคำตอบ → ตรวจ → อ่าน error → แก้และตรวจซ้ำ → สรุปสิ่งที่เรียนรู้**

## 1. อ่านโจทย์เหมือนอ่านคำขอจากเพื่อนร่วมงาน

จดให้ได้ว่าใครจะใช้โปรแกรม ปัญหาคืออะไร ได้ input แบบใด ต้องส่ง output อะไร มีข้อห้ามอะไร และกรณีขอบคืออะไร ตัวอย่างเช่น ค่าจัดส่งอาจขึ้นกับยอดซื้อและเขต ต้องตกลงก่อนว่าเกณฑ์ส่งฟรีใช้ `ยอด >= เกณฑ์` หรือ `ยอด > เกณฑ์` และเขตที่ไม่รู้จักต้องทำอย่างไร

อย่าเดาความหมายจากชื่อฟังก์ชันอย่างเดียว อ่านประเภทข้อมูลและตัวอย่างในโจทย์ด้วย ถ้าข้อมูลเป็นตัวเลขแทนกำไร ให้ถามตัวเองว่าศูนย์นับเป็นกำไรหรือไม่ ถ้ารายการว่าง ควรคืนค่าอะไร

## 2. วางแผนก่อนเขียน

เขียนขั้นตอนเป็นภาษาคนหรือ pseudocode สั้น ๆ เช่น:

1. รับยอดรวมและเขตจัดส่ง
2. ตรวจว่ายอดไม่ติดลบ
3. เลือกค่าจัดส่งตามเขต
4. ถ้ายอดถึงเกณฑ์ ให้ค่าจัดส่งเป็นศูนย์
5. คืนค่าจัดส่งและยอดสุทธิ

จากนั้นแปลงทีละขั้นเป็น Python เลือกชื่อตัวแปรที่บอกความหมาย หลีกเลี่ยงการเขียนสูตรยาวบรรทัดเดียวถ้ายังอ่านไม่ออก

## 3. พิมพ์และทดลอง

พิมพ์ตัวอย่างในบทเรียนด้วยตนเอง รัน แล้วเปลี่ยนค่าหนึ่งอย่างเพื่อทำนายผลก่อนดูหน้าจอ วิธีนี้ช่วยตรวจว่าคุณเข้าใจความสัมพันธ์ระหว่าง input และ output หรือเพียงคัดลอกโค้ด

สำหรับข้อที่ให้สร้างฟังก์ชัน ให้ตรวจว่า signature ตรงตามโจทย์ ใช้ `return` ส่งผลกลับ และไม่พิมพ์ผลแทนการคืนค่า เว้นแต่โจทย์กำหนดให้โปรแกรมแสดงข้อความ

## 4. ตรวจแบบมีแผน

ลองอย่างน้อย:

- กรณีทั่วไปจากโจทย์
- ค่าต่ำสุดหรือรายการว่าง
- ค่าที่อยู่ตรงขอบเกณฑ์
- ค่าผิดชนิดหรือรูปแบบผิด ถ้าโจทย์กำหนดให้รองรับ
- ค่าที่ทำให้เกิดศูนย์ หารด้วยศูนย์ หรือค่าติดลบ

คำสั่ง `python practice.py run` ใช้ทดลองกรณีตัวอย่างแรก ส่วน `python practice.py check` รันกรณีตรวจทั้งหมดของข้อปัจจุบัน อ่านชื่อ test และข้อความผิดพลาด แล้วหาว่าข้อสมมติใดไม่ตรง

## 5. อ่านข้อผิดพลาด

อ่านบรรทัดท้ายของ traceback เพื่อดูชนิดข้อผิดพลาด และดูบรรทัดที่ระบุในไฟล์ ค่อย ๆ แก้ทีละปัญหา อย่าลบเงื่อนไขหรือปิด assertion เพียงเพื่อให้ test ผ่าน คู่มืออยู่ที่ [ข้อผิดพลาด Python ที่พบบ่อย](common-python-errors.md)

## 6. ใช้ hint และ solution อย่างรับผิดชอบ

ขอ hint ระดับ 1 ก่อน ถ้ายังติดให้ไล่ระดับ 2 และ 3 หลังดูแต่ละใบให้กลับไปลองเขียนเอง คำสั่ง solution และ explain เตือนก่อนเปิด และเก็บประวัติการเปิดไว้ การผ่านหลังใช้ความช่วยเหลือเป็น `PASSED_WITH_HELP` ให้ใช้โอกาสครั้งถัดไปทำ assessment variant ใหม่โดยไม่เปิดคำตอบ เพื่อทดสอบความเข้าใจของตนเอง

อย่าคัดลอก solution แล้วเดินต่อทันที หลังอ่านแล้วให้ปิดเฉลย อธิบายแต่ละบรรทัดด้วยคำของตนเอง เขียนใหม่จากความจำ และเปลี่ยน input เพื่อตรวจพฤติกรรม

## 7. วิธีรู้ว่าพร้อมไปต่อ

คุณควรเล่าได้ว่าโค้ดรับอะไร ทำขั้นตอนใด คืนหรือแสดงค่าอะไร และมีข้อจำกัดตรงไหน ลองสร้าง test ใหม่ได้ และแก้โจทย์ที่เปลี่ยนบริบทแต่ใช้แนวคิดเดิม หากทำได้เพียงจำรูปแบบ solution ให้ฝึกอีกหนึ่งตัวอย่างก่อน
